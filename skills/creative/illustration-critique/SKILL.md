# Illustration Critique

Produces a structured critique, not a redraw. This skill doesn't generate or edit
images — if the user wants new artwork created, that's a different tool; this one
reviews what already exists.

## Process

1. **Get the artwork.** If no image or description has been shared yet, ask for it
   before anything else — don't critique from assumption.
2. **Establish intent.** Ask (or infer from context) what the piece is for — a
   quick sketch, a finished piece, a production-ready character turnaround — since
   the bar for "done" differs. Critiquing a thumbnail against finished-piece
   standards wastes the artist's time on polish they weren't asking for yet.
3. **Check in this order** — each is foundational to the next, so a problem found
   early usually explains symptoms further down:
   - **Proportion/anatomy** — internally consistent, whatever the style (realism
     is a choice, not the bar; inconsistency *within the chosen style* is the
     actual defect).
   - **Perspective** — do all elements share one coherent vanishing-point/horizon
     logic, or does something float in a different space than the rest?
   - **Value structure** — squint-test it (or reason in grayscale terms): is there
     a clear light/dark read that establishes a focal point, or is everything
     mid-value and equally weighted?
   - **Composition** — where does the eye enter and travel? Is there one clear
     focal point, or is attention split with no hierarchy?
   - **Color harmony** — do the colors share a coherent temperature/saturation
     logic, or do they fight each other without that being an intentional clash?
4. **Report specific, fixable notes, not vibes.** "The sword arm reads about 15%
   shorter than the other, which breaks the pose's silhouette" beats "proportions
   feel off." Every note names the specific element, what's wrong, and a concrete
   fix.
5. **Separate "broken" from "a style choice you may not want flagged."** An element
   drawn unrealistically on purpose, as part of a stylized design language, is not
   the same defect as one drawn unrealistically by accident. If it's ambiguous
   which one you're looking at, ask rather than flag it as a fix.

## Reporting format

```
## <Category>

- <specific element> — <what's wrong> — <concrete fix>
- ...
```
